EXACT INTENDED ROW SCORING
Representative P2 formula:
IF(E2<>"Yes","",IF(J2="Yes",100,IF(I2="Yes",50,IF(AND(F2="Yes",OR(G2="Yes",H2="Yes")),30,IF(F2="Yes",20,10)))))

Priority: no E=Yes means blank; otherwise Sign Up 100; Strong Follow-Up 50; Connected with Text OR Email 30; Connected 20; Attempted 10. Stages in Q follow the same priority. The highest applicable score replaces earlier stages. The source's explanatory incremental labels must not be interpreted as additional credits after reaching a higher stage.

The source formula can award 50/100 without Connected=Yes, provided Attempt=Yes. Do not silently alter historical source values; mark contradictory/unsupported outcomes for review. The new workflow may have supervisor-confirmed externally sourced leads, but must not invent a connected call for them. New-app scoring uses confirmed milestones and a qualifying activity, a deliberate governance improvement over editable source flags.

OTHER VERIFIED REPORTING ISSUES
1. Chart 2 is titled 'Calls by Employee (month-to-date)' but references Dashboard!D22:D44, the daily call count. Chart 1 uses the month-to-date funnel helper range. Chart titles, date filters and query grain must agree.
2. Dashboard!P7 sums S22:S44. Those helpers count G=Yes only, so the displayed touch metric omits email-only rows. Define and show SMS, email and combined touch metrics separately.
3. The daily table's Follow-Ups value counts I=Yes (Strong Follow-Up), not all follow-up tasks or K's declared count. The new app must distinguish them.
4. Connection, strong and sign-up COUNTIFS are not consistently constrained by E=Yes, while quality is. This snapshot has 33 rows across all dates with a downstream Yes flag but no E=Yes, including 32 in October. They are review items or separate channel activity, not automatic attempted-call credit. Across all dates one connected flag has no attempt.
5. Dashboard!P9 counts representatives with positive monthly calls; it does not use the RosterActive named range as its participation denominator. Treat attendance, active employment, scheduled workdays and 'reported any calls' as different concepts.
6. Whole-column INDIRECT/COUNTIFS/SUMIFS and many prefilled formulas create spreadsheet overhead. A database should use indexed events and incremental, authorized aggregates instead of translating the spreadsheet into repeated full-table scans.

DUPLICATE AND VALIDATION LIMITATIONS
The workbook has local conditional-format duplicate rules with misaligned references, for example a provider-name rule using COUNTIF(B:B,B12775)>1 over earlier row ranges. These do not establish cross-agent normalized-phone ownership.

A conservative digits-only pass found 5,917 repeated ten-digit telephone keys, including 3,382 appearing on more than one operator sheet. This pass strips punctuation and a leading 1 from eleven-digit strings and considers only resulting ten-digit keys; it is not a complete phone parser, not telephone validity verification, and not a count of duplicate clients. Use a proper phone parser and reviewed shared-number handling in the actual migration. No raw numbers are included in this package.

The existing phone/email validation does not provide a complete normalization or identity policy. The workbook has no dependable immutable actor IDs, server event timestamps, lock deadlines, exclusive ownership constraints, hierarchical access controls, meeting confidentiality or release approval records. Those are new application requirements, not existing spreadsheet capabilities to preserve.

MIGRATION CONSEQUENCES
- Import raw business inputs and provenance, never formulas as executable authority.
- Reconstruct scores from E:J with versioned rules; preserve discrepancies for review.
- Ask authorized management to map operator sheets to stable accounts; names are not identity keys.
- Skip empty/formula-only template rows and do not auto-create ten Unassigned users.
- Reconcile legitimate repeated calls separately from duplicate import rows.
- Import dates as historical business dates; row order cannot prove who called first.
- Supervisor-review strong-follow-up/sign-up claims; do not trigger historical celebrations or new external communications.
- Keep original file unchanged and record its checksum, import ID, sheet, row and transformations.

The sanitized totals are suitable for a developer's architecture review. The original workbook should be supplied privately only when historical import work is authorized and necessary.
