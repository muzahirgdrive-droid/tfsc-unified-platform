PURPOSE AND NON-NEGOTIABLE OUTPUT REQUIREMENTS
Generate BAA and/or Services Agreement from practice/provider legal name, address,
effective dates, selected company, service lines/prices and agreed terms. Output
editable DOCX plus PDF, original letterhead on each page, Page X of Y, uniformly
Times New Roman justified body and bold headings 16/14/13 pt, safe text bounds,
signature positioned on line and a continuation-protecting execution section.
BAA text uses the supplied approved-source DOCX/JSON with only supported variable
substitutions. Do not rewrite it merely to improve legal language. Service wording
is modular; where source wording was supplied, preserve it. Legal/compliance review
is not replaced by software or historical generated wording.

DATA / PERMISSIONS
Local SQLite WAL; hosted PostgreSQL. Native tables: users, sessions, clients,
contracts, documents, audit, jobs, settings, throttle. Added bridge: crm_actor_links,
crm_client_links, crm_bridge_handoffs, crm_bridge_nonces, agreement_reviews;
optional OIDC accounts/states. Schema: Alembic migrations (migrate.py, run at start-up; pre-Alembic installs are stamped first).
User role: own clients/contracts; permitted companies only. Admin: assigned users
and their scope; may create constrained users. Super Admin: all. A subordinate's
company rights are intersected with active parent Admin rights. No CRM org_id
tenant hierarchy is shared here. Never copy CRM role rank into TFSC role behavior.
Client uniqueness is owner + normalized-name hash, not a canonical global client
identity. One CRM client may map to owner-specific TFSC client records.
Contracts immutable revision payload/folder metadata; documents contain full bytes,
SHA256, size, filename, type and disk path. Download falls back to retained DB bytes
through existing implementation. Storing large blobs has storage/backup costs.

DOCUMENT WORKFLOW
Save editable draft -> validate -> queue with Idempotency-Key -> worker claim.
PostgreSQL uses FOR UPDATE SKIP LOCKED; SQLite uses compare-and-swap claim.
Five pending jobs per user; lease currently 30 minutes; expired running job fails
and requires explicit retry, not blind replay of possibly published output.
Worker rechecks authorization, builds all docs in a staging folder, then records
blobs and publishes disk copies. Disk and SQL are not one atomic resource; inspect
crash recovery/orphan cleanup rather than assuming transaction atomicity across both.
Output root/practice slug/entity key/owner prefix/agreement subfolder/revision files.
Each generated revision retained. Selected document_types controls BAA/SA/both.
Windows renderer uses installed activated Word. Linux uses LibreOffice. Page counts
may differ by renderer/font; install licensed Times New Roman and visually inspect
target-machine outputs. Embedded PAGE/NUMPAGES fields display Page X of Y.
Local folder browser can select permitted local paths. Hosted paths are constrained
to TFSC_OUTPUT_ROOT; it cannot browse a remote browser user's laptop filesystem.

REVIEW GATE
Enabled if TFSC_REQUIRE_APPROVAL=1, a CRM link exists, or a client has a review.
Owner submits exact draft; separate administrator approves within scope/company.
Hash covers payload, templates, assets/fonts, renderer/content source and signature
bytes/metadata. Changed source/assets invalidates approval. Worker checks before
render and before release. State submitted -> approved/changes_requested -> queued
-> issued; superseded older submitted/approved records. Job failures can leave
queued review metadata inconsistent: reconcile this as a known improvement.
Immutable asset snapshot/versioning would improve file-change race resistance.
Review UI shows draft metadata; full document visual approval preview is incomplete.
