WHAT NEEDS THE OWNER (identical in both archives)
Never paste secret values into a chat or a ticket: put them in the server's .env / Kubernetes secrets.

HOSTING AND NAMES
[ ] Choose the go-live layout: one VPS with infra/compose, or Kubernetes with infra/helm. Measured on one
    4-vCPU VM: 800 agents at the 20 s-think profile meet the §24 targets; beyond that, put PostgreSQL on its
    own host (docs/PERFORMANCE.md). On Kubernetes use a CNI that enforces NetworkPolicies, and tune PostgreSQL.
[ ] Domain names and DNS records: CRM (e.g. crm.<company>), TFSC Agreements, SSO (Keycloak).
    Caddy (compose) or the Ingress obtains TLS certificates once DNS points at the server.
[ ] Off-site backups: an S3 bucket at another provider/region for the encrypted pgBackRest copies
    (infra/compose/backup-offsite.env.example), versioning or object lock on. The bundled storage already
    keeps the daily audit anchors in an object-lock bucket; choose its retention (default seven years).
[ ] Keep BACKUP_PASSPHRASE (and the off-site one) in the company password manager: without it no backup
    can be restored. Read docs/runbooks/backups-and-restore.md once; Security Center -> Backups shows the
    daily automated restore test.

SECRETS TO GENERATE ON THE SERVER (names in ENVIRONMENT-NAMES.json, examples in infra/compose/.env.example)
[ ] CRM_FIELD_KEY (base64 of 32 random bytes) and CRM_PHONE_KEY_SECRET — back them up offline: losing
    them makes encrypted fields and phone keys unreadable.
[ ] Bridge secret (same value as CRM_TFSC_BRIDGE_SECRET and TFSC_CRM_SHARED_SECRET, 32+ characters).
[ ] PostgreSQL password, Keycloak admin password, OIDC client secrets, CRM_METRICS_TOKEN,
    CRM_KEYCLOAK_CLIENT_SECRET (the realm's tfsc-crm-provisioner client), GRAFANA_ADMIN_PASSWORD,
    BACKUP_PASSPHRASE.
[ ] Object-storage keys for the CRM (S3_ACCESS_KEY / S3_SECRET_KEY): on an external provider, give them
    no right to delete objects.

SIGN-IN AND EMAIL
[ ] Keycloak: use the bundled realm (infra/keycloak/realm-tfsc.json) or federate the company directory.
    Every user's email must match their CRM account; Supervisors and above go in the group
    supervisors-and-above (TOTP required).
[ ] SMTP account (SMTP_* in .env): Keycloak sends the invitations (set password, TOTP enrolment) and the
    password-reset emails. Verified with a local mail sink; send one of each in staging.

INTEGRATIONS
[ ] Google Calendar: a Google Cloud project with an OAuth client (CRM_GOOGLE_CLIENT_ID / _SECRET) and
    the organizer account(s) that should own meetings; then test in staging.
[ ] Vonage: keep tel: links, or provide the custom URI template; say whether call logging via the
    Vonage API is required.
[ ] Error tracking: Sentry DSNs (CRM_SENTRY_DSN, CRM_SENTRY_DSN_WEB, TFSC_SENTRY_DSN) or none.
[ ] Who receives alerts: add an Alertmanager (email/chat) for infra/observability/alerts.yml (service down,
    5xx rate, latency, outbox, backups, restore test, WAL archiving). Grafana and Prometheus are bundled
    (--profile observability).

TFSC AGREEMENTS
[ ] Install the private signature images on the TFSC server (python manage.py install-signatures);
    they are never in git or in images.
[ ] Server renderer is LibreOffice on Linux: approve its pagination against the Word originals, or run
    a Windows renderer host.
[ ] Legal review of any agreement text beyond the supplied service scopes; choose an e-signature
    provider if signatures must be executed electronically.
